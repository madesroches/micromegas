1//! `OwnershipRewrite` -- the row-level filter.
2//!
3//! An `AnalyzerRule` that injects an audience-filtering predicate into every
4//! `MaterializedView`-backed `TableScan` a query plan touches, based on the caller's `ReadScope`
5//! (`read_scope.rs`) and [`super::read_scope::IsolationConfig`]'s
6//! `MICROMEGAS_PUBLIC_VIEW_SETS`.
7//!
8//! ## `ReadScope::All` is a true no-op
9//!
10//! `ReadScope::All` is the internal/maintenance marker -- never the output of a real `ReadPolicy`
11//! (see `read_scope.rs`). `analyze()` returns the plan unchanged when constructed with it, and
12//! `query.rs::make_session_context` does not even construct this rule for `ReadScope::All`
13//! callers, so their `ViewFactory` need not carry `processes`/`streams` either.
14//!
15//! ## The physical `audience` column
16//!
17//! `blocks`, `processes`, `streams`, `log_entries`, `measures`, and `log_stats` each carry a
18//! physical `audience` column -- declared non-nullable on `blocks`/`log_entries`/`measures`, and
19//! non-null by construction (though declared nullable in their inferred `SqlBatchView` schema) on
20//! `processes`/`streams`/`log_stats` -- extracted once from Postgres's own `audience` column at
21//! the `blocks` view's materialization (its own row's stamp) and propagated structurally into
22//! every downstream view. Those six views are consequently filtered with a bare `Filter` on that
23//! column (the column-filter branch in the table below): no semi-join, no `property_get`, no
24//! per-process aggregate. `async_events`, `thread_spans`, `net_spans`, `otel_spans`, and `images`
25//! don't carry the column. They keep the `process_id`/`EXISTS` machinery below, which still
26//! resolves through `__processes__partitions`, but only for a scan that is *not* a guarded
27//! `view_instance(...)` -- see the skip rule in the Branch table below.
28//!
29//! ## One audience per row, not derived from the process (surviving branches only)
30//!
31//! `__processes__partitions` (the raw, un-merged `SqlBatchView` partitions `self.processes_source`
32//! scans) can carry more than one historical row per `process_id` -- the partition-level
33//! `GROUP BY` in `processes_view.rs`'s transform query only collapses rows *within* a partition,
34//! not across a long-lived process's entire history. Filtering the six column-carrying views one
35//! row at a time (the column-filter branch) is sound without any aggregate: every row now carries
36//! its own stamp from the moment it was written, so there is nothing to reconcile across rows of
37//! the same process. The one exception is a legacy, pre-v8 row with no `audience` column at all --
38//! `COALESCE` resolves that to the deployment default at read time. The `net_spans`/
39//! `otel_spans`/`images` semi-join branch and the `async_events`/`thread_spans` `EXISTS` branches
40//! still resolve through `per_process_audience` -- `Aggregate(GROUP BY process_id, MAX(audience)
41//! AS resolved_audience)` -- for a scan of those five that is *not* a guarded instance, since they
42//! have no `audience` column of their own to filter directly. A guarded instance skips the
43//! predicate entirely (see the Branch table below).
44//!
45//! ## Branch table
46//!
47//! Keyed on `MaterializedView::get_view().get_file_schema()`: whether it has an `audience` field,
48//! failing that whether it has a `process_id` field -- not on a hardcoded view-set list, so a
49//! future view set that gains either column falls into the matching branch automatically:
50//!
51//! | View set | Branch |
52//! |---|---|
53//! | `processes`, `streams`, `blocks`, `log_entries`, `measures`, `log_stats` | `column filter`: direct `audience IN (...)` filter on the view's own column -- no join |
54//! | `net_spans`, `otel_spans`, `images`, `async_events`, `thread_spans`, scanned as a guarded, non-`'global'` `view_instance(...)` | `skip`: no predicate at all -- `MaterializedView::instance_is_audience_guarded()` reports `AudienceGuard::authorize_view_instance` already denies an unauthorized caller before any row is read, so the subquery predicates below would be redundant |
55//! | `net_spans`, `otel_spans`, `images`, not a guarded instance | `semi-join`: `process_id IN (subquery)` against `per_process_audience` (outer `process_id` cast to `Utf8`: it is `Dictionary(Int32, Utf8)` in these, and nothing coerces an uncorrelated `IN` subquery's join keys once `DecorrelatePredicateSubquery` turns it into a `LeftSemi` join -- the analyzer's own `TypeCoercion` has already run by the time this rule executes) |
56//! | `async_events`, not a guarded instance | no `process_id` column either -- `async_events EXISTS`: literal-valued `EXISTS`, keyed on `get_view_instance_id()` (the process_id string, canonicalized -- see `canonical_view_instance_id`) |
57//! | `thread_spans`, not a guarded instance | no `process_id` **or** `stream_id` column -- `thread_spans EXISTS`: two-hop literal `EXISTS`, through `streams` (`get_view_instance_id()` is the stream_id string, canonicalized the same way) |
58//! | anything in `public_view_sets` | `public`: no predicate at all -- checked before any of the above |
59//! | anything else | `analyze()` returns `Err` (`DataFusionError::Plan`) rather than silently leaving the scan unfiltered -- a future view set must add itself to this table, not fall through |
60//!
61//! Adding a new view set to a `ViewFactory` means adding it to this table too, and to the match
62//! arms in [`OwnershipRewrite::predicate_for`] below.
63//!
64//! ## No I/O in `analyze()`
65//!
66//! `in_subquery`/`exists` build uncorrelated subquery `Expr`s; `DecorrelatePredicateSubquery` (an
67//! optimizer, not analyzer, rule) turns them into joins later. `processes_source`/`streams_source`
68//! come from `MaterializedView::new(..., query_range: None)`, which is synchronous and does no I/O
69//! -- the actual `processes`/`streams` scans happen during normal execution, exactly like
70//! `TableScanRewrite`'s injected time filter.
71//!
72//! ## The `audience` column is server-written and authenticated
73//!
74//! `processes`, `streams`, and `blocks` are each stamped with their own `audience` column at
75//! write time, from the authenticated credential's `AuthContext.bound_audience`
76//! (`resolve_write_audience`), and a client can neither assert nor forge that stamp
77//! (`strip_reserved_properties` drops any client-supplied `micromegas.*` property, and there is
78//! no property to re-assert in the first place any more -- the stamp is a physical column, not a
79//! property). A credential carrying no bound audience resolves to the deployment default at the
80//! HTTP write edge and is stamped with it explicitly, the same as any other audience -- only a
81//! legacy, pre-v8 row keeps a NULL column, resolved to the deployment's
82//! `MICROMEGAS_DEFAULT_AUDIENCE` where the audience is *read* instead (see `crate::audience`'s
83//! module doc). Admin replication (`replication.rs`) now hard-fails on a missing `audience`
84//! column rather than ever writing a row with none. Registration
85//! (`insert_process`/`register_otel_process`) rejects a same-`process_id`, different-audience
86//! re-registration outright -- needed because the OTLP `process_id` derivation formula is public,
87//! so without this guard a credential could pre-register (via the native path) the exact
88//! `process_id` a victim audience's OTLP producer would later derive, silently exposing that
89//! audience's data to the squatter; this is a confidentiality gap, not merely an integrity one.
90//! The stream-side mirror, `check_stream_audience_conflict`, closes the equivalent
91//! re-pointed-credential gap for `streams`.
92//!
93//! **What remains open, tracked separately:**
94//! - **The five instance-only view sets** (`net_spans`, `otel_spans`, `images`, `async_events`,
95//!   `thread_spans`) **and the per-process JIT `view_instance` path** still resolve their audience
96//!   *label* through the owning process's/stream's row rather than a genuine per-row column of
97//!   their own -- via the call-level guard's instance check (`AudienceGuard::authorize_view_instance`,
98//!   `IdKind::ProcessOrStream`) for the guarded `view_instance(...)` scan every production caller
99//!   takes, not by a predicate this rule injects (see the skip in the Branch table above). The
100//!   cross-audience *injection* scenario (an attacker's block naming a victim's
101//!   `process_id`/`stream_id`) is closed for both, as a side effect of the mismatch predicate on
102//!   `blocks_view`'s own materialization -- except against a victim whose `processes`/`streams`
103//!   row is a legacy, pre-v8 NULL-audience row (next bullet).
104//! - **The NULL-anchor window.** A `processes`/`streams` row registered before its ingestion
105//!   binary supported per-row stamping keeps `audience = NULL` for its entire remaining life
106//!   (rows are immutable, no backfill). The mismatch predicate's NULL-tolerant pass-through lets
107//!   a mismatched block through unchecked against such a row for as long as it exists. This is
108//!   an accepted, bounded limitation over already-public legacy data, bounded by the deploy-order
109//!   requirement (every ingestion replica upgraded) and shrinking as legacy rows age out under
110//!   retention.
111//!
112//! There is no in-product enforcement knob left for either surface; the mitigation is
113//! operational -- provision only audience-bound DB-backed ingestion credentials, and don't run
114//! ingestion with an env-keyring key, OIDC, or `--disable-auth` alongside them -- see this
115//! stage's `CHANGELOG.md` entry.

134/// Injects an audience predicate into every `MaterializedView` scan (see the module doc comment).

155impl OwnershipRewrite {
156    /// `processes_source`/`streams_source` must be built from `MaterializedView::new(...,
157    /// query_range: None)` over the raw partitions (equivalent to `__processes__partitions` /
158    /// `__streams__partitions`) -- see `query.rs::make_session_context`: the audience lookup must
159    /// be time-unbounded, and must not go through the `SqlBatchView`-merged `processes`/`streams`
160    /// named tables. Used only by the semi-join/`async_events`/`thread_spans` branches -- the six
161    /// column-carrying views need neither.
162    pub fn new(
163        read_scope: ReadScope,
164        public_view_sets: Vec<String>,
165        processes_source: Arc<dyn TableSource>,
166        streams_source: Arc<dyn TableSource>,
167    ) -> Self {
168        Self {
169            read_scope,
170            public_view_sets,
171            processes_source,
172            streams_source,
173        }
174    }

176    /// `Aggregate(GROUP BY process_id, MAX(audience) AS resolved_audience)` over the raw,
177    /// time-unbounded `processes` partitions -- built once per `analyze()` call and reused at
178    /// every scan site the traversal visits (see the module doc comment). Only reached by the
179    /// semi-join/`async_events`/`thread_spans` branches now that `processes` itself carries a
180    /// physical `audience` column and filters it directly (the column-filter branch); the
181    /// aggregate still exists for those three because they have no `audience` column of their
182    /// own, not to reconcile disagreeing rows -- a process's own `audience` column never
183    /// disagrees across rows, so `MAX` is just a way to pull the single value out of the group.
184    fn per_process_audience(&self) -> datafusion::error::Result<LogicalPlan> {
185        LogicalPlanBuilder::scan(
186            "__processes__partitions",
187            self.processes_source.clone(),
188            None,
189        )?
190        .aggregate(
191            vec![col("process_id")],
192            vec![max(col("audience")).alias("resolved_audience")],
193        )?
194        .build()
195    }
196
197    /// The caller's audience set. Only ever called after `analyze()` has short-circuited on
198    /// `ReadScope::All`, so the `All` arm here is unreachable in practice; it degrades to "no
199    /// audiences" rather than panicking if that invariant is ever violated.
200    fn audiences(&self) -> &[String] {
201        match &self.read_scope {
202            ReadScope::All => &[],
203            ReadScope::Audiences(a) => a,
204        }
205    }
206
207    /// `resolved_audience IN (audiences)`, or `lit(false)` when `audiences` is empty -- the
208    /// fail-closed reading of "caller has no audiences" rather than emitting `IN ()` and leaving
209    /// its behavior to DataFusion (`ReadScope::Audiences` can legitimately resolve to an empty
210    /// set -- `public` has no built-in read grant, so a caller matching no grant at all,
211    /// including the seeded `('public', 'read', '*')` row, resolves to the empty set, and that
212    /// empty set is now reachable in production, not just in tests). No `coalesce` here: the column is
213    /// non-null by construction, because the extraction sites already coalesced a
214    /// never-stamped process's missing property to the deployment default before it was
215    /// materialized.
216    fn resolved_predicate(&self) -> Expr {
217        let audiences = self.audiences();
218        if audiences.is_empty() {
219            return lit(false);
220        }
221        col("resolved_audience").in_list(
222            audiences
223                .iter()
224                .map(|a| lit(ScalarValue::Utf8(Some(a.clone()))))
225                .collect(),
226            false,
227        )
228    }
229
230    /// The column-filter branch: `audience IN (caller audiences)`; `false` for an empty set
231    /// (fail-closed, as [`Self::resolved_predicate`] already does). The column is declared `NOT NULL` on
232    /// `blocks`/`log_entries`/`measures` and non-null by construction (though declared nullable)
233    /// on `processes`/`streams`/`log_stats`, so there is no unstamped case either way.
234    fn audience_column_predicate(&self, table_name: &TableReference, field: &Field) -> Expr {
235        let audiences = self.audiences();
236        if audiences.is_empty() {
237            return lit(false);
238        }
239        let raw = Expr::Column(Column::new(Some(table_name.clone()), "audience"));
240        // This rule runs after DataFusion's own TypeCoercion pass, so the Dictionary(Int32, Utf8)
241        // column every one of the six views carries must be cast to compare against Utf8
242        // literals. The cast is not a pruning barrier: `PruningPredicate` rewrites `cast(col) op
243        // lit` by applying the same cast to the column's min/max statistics
244        // (`datafusion-pruning`'s `rewrite_expr_to_prunable`), and a Dictionary -> Utf8 cast is on
245        // its supported list (`verify_support_type_for_prune` unwraps dictionaries), with `IN`
246        // lists up to 20 items expanded to such comparisons. The bare-column arm below is
247        // therefore just a no-op-cast skip, kept for a future view that carries plain `Utf8`.
248        let lhs = if field.data_type() == &DataType::Utf8 {
249            raw
250        } else {
251            cast(raw, DataType::Utf8)
252        };
253        lhs.in_list(
254            audiences
255                .iter()
256                .map(|a| lit(ScalarValue::Utf8(Some(a.clone()))))
257                .collect(),
258            false,
259        )
260    }
261
262    /// The semi-join branch's shared `IN`-subquery plan: `per_process_audience` filtered by
263    /// `resolved_predicate`, projected down to `process_id` alone -- the one column an
264    /// `InSubquery` may project.
265    fn in_subquery_plan(
266        per_process_audience: &LogicalPlan,
267        resolved_predicate: &Expr,
268    ) -> datafusion::error::Result<Arc<LogicalPlan>> {
269        Ok(Arc::new(
270            LogicalPlanBuilder::from(per_process_audience.clone())
271                .filter(resolved_predicate.clone())?
272                .project(vec![col("process_id")])?
273                .build()?,
274        ))
275    }
276
277    /// The `async_events` branch's literal-valued `EXISTS`: `per_process_audience` filtered down
278    /// to the single process named by `process_id_literal`, conjuncted with `resolved_predicate`.
279    /// No projection: unlike
280    /// `InSubquery`, `EXISTS` has no single-column-projection requirement, so the two-column
281    /// (`process_id`, `resolved_audience`) shape is fine.
282    fn exists_for_process(
283        per_process_audience: &LogicalPlan,
284        resolved_predicate: &Expr,
285        process_id_literal: &str,
286    ) -> datafusion::error::Result<Expr> {
287        let subquery = LogicalPlanBuilder::from(per_process_audience.clone())
288            .filter(
289                col("process_id")
290                    .eq(lit(process_id_literal))
291                    .and(resolved_predicate.clone()),
292            )?
293            .build()?;
294        Ok(exists(Arc::new(subquery)))
295    }
296
297    /// The `thread_spans` branch's two-hop literal `EXISTS`: resolve `stream_id_literal` (the
298    /// `thread_spans` `view_instance_id`) through `streams` into the process it belongs to, then
299    /// apply the same `per_process_audience`/`resolved_predicate` check the column-filter branch
300    /// uses directly.
301    fn exists_for_stream(
302        &self,
303        per_process_audience: &LogicalPlan,
304        resolved_predicate: &Expr,
305        stream_id_literal: &str,
306    ) -> datafusion::error::Result<Expr> {
307        let subquery =
308            LogicalPlanBuilder::scan("__streams__partitions", self.streams_source.clone(), None)?
309                .filter(col("stream_id").eq(lit(stream_id_literal)))?
310                .join(
311                    LogicalPlanBuilder::from(per_process_audience.clone())
312                        .filter(resolved_predicate.clone())?
313                        .build()?,
314                    JoinType::Inner,
315                    (vec!["process_id"], vec!["process_id"]),
316                    None,
317                )?
318                .build()?;
319        Ok(exists(Arc::new(subquery)))
320    }

322    /// Parses `view.get_view_instance_id()` as a `Uuid` and returns its canonical
323    /// lowercase-hyphenated string form -- the form actually stored in `process_id`/`stream_id`
324    /// columns. `Uuid::parse_str` accepts several equivalent textual spellings (uppercase,
325    /// hyphen-less, braced) of the same UUID, but
326    /// only this canonical form round-trips through the data; using the raw, caller-supplied
327    /// spelling directly in a literal comparison would silently fail to match for any other
328    /// spelling of a legitimately materialized instance id. Defensive `Err` on parse failure --
329    /// the view constructors (`AsyncEventsView::new`/`ThreadSpansView::new`) already validate this
330    /// as a UUID at construction time, so this should not happen in practice.
331    fn canonical_view_instance_id(
332        view_set_name: &Arc<String>,
333        view: &Arc<dyn super::view::View>,
334    ) -> datafusion::error::Result<String> {
335        let raw = view.get_view_instance_id();
336        Uuid::parse_str(raw.as_str())
337            .map(|uuid| uuid.hyphenated().to_string())
338            .map_err(|e| {
339                DataFusionError::Plan(format!(
340                    "OwnershipRewrite: view set '{view_set_name}' view_instance_id '{raw}' is \
341                     not a valid UUID: {e}"
342                ))
343            })
344    }

346    /// Builds the predicate to wrap `mat_view`'s scan in. `Ok(None)` means "no predicate at all",
347    /// for either of two reasons: the public-view-set skip, or a guarded `view_instance(...)`
348    /// scan that `MaterializedView::instance_is_audience_guarded()` reports is already fully
349    /// authorized by `AudienceGuard::authorize_view_instance` (the call-level guard); `Err` is the fallback
350    /// for a view set matching none of the branches -- see the module doc comment's branch table.
351    fn predicate_for(
352        &self,
353        table_name: &TableReference,
354        mat_view: &MaterializedView,
355        per_process_audience: &LogicalPlan,
356        resolved_predicate: &Expr,
357        in_subquery_plan: &Arc<LogicalPlan>,
358    ) -> datafusion::error::Result<Option<Expr>> {
359        let view = mat_view.get_view();
360        let view_set_name = view.get_view_set_name();
361        if self
362            .public_view_sets
363            .iter()
364            .any(|s| s.as_str() == view_set_name.as_str())
365        {
366            return Ok(None);
367        }
368        // A guarded, non-`'global'` `view_instance(...)` scan is already fully authorized by
369        // `AudienceGuard::authorize_view_instance` before any row is read (see
370        // `MaterializedView::instance_is_audience_guarded`'s doc comment), so the semi-join/
371        // `async_events`/`thread_spans` subquery predicates below are redundant for it. This
372        // assumes a guarded instance's rows can never legitimately span more than one process --
373        // true for today's five view sets, but a future guarded view set whose instance can
374        // legitimately span more than one process would need to revisit this before its arm gets
375        // the same skip.
376        let skip = mat_view.instance_is_audience_guarded();
377        // The column-filter branch: views carrying a physical `audience` column -- processes,
378        // streams, blocks, log_entries, measures, log_stats (global and per-process instances
379        // alike). Filtered directly, no semi-join, no property_get. Checked ahead of the
380        // semi-join branch so a view set that has *both* an `audience` and a `process_id` column
381        // (all six do) takes this cheaper branch; keyed on schema introspection, so a view set
382        // that gains the column later upgrades automatically with no edit here.
383        if let Ok(field) = view.get_file_schema().field_with_name("audience") {
384            return Ok(Some(self.audience_column_predicate(table_name, field)));
385        }
386        // Qualified with the outer scan's own table name: once `DecorrelatePredicateSubquery`
387        // joins this scan with `in_subquery_plan`'s subquery, the combined schema holds a
388        // `process_id` column from both sides, so a bare, unqualified `col("process_id")` is
389        // ambiguous and `into_optimized_plan()` fails.
390        let outer_process_id = Expr::Column(Column::new(Some(table_name.clone()), "process_id"));
391        if view.get_file_schema().field_with_name("process_id").is_ok() {
392            // The semi-join branch: process_id-**column** views with no `audience` column of
393            // their own -- net_spans, otel_spans, images.
394            if skip {
395                return Ok(None);
396            }
397            return Ok(Some(in_subquery(
398                cast(outer_process_id, DataType::Utf8),
399                in_subquery_plan.clone(),
400            )));
401        }
402        if view_set_name.as_str() == "async_events" {
403            // The async_events branch: process-scoped, no process_id column -- the
404            // view_instance_id *is* the process_id string (`AsyncEventsView::new` parses it as
405            // a `Uuid`). Canonicalized
406            // before building the literal -- see `canonical_view_instance_id`'s doc comment for why.
407            if skip {
408                return Ok(None);
409            }
410            let process_id_literal = Self::canonical_view_instance_id(&view_set_name, &view)?;
411            return Ok(Some(Self::exists_for_process(
412                per_process_audience,
413                resolved_predicate,
414                process_id_literal.as_str(),
415            )?));
416        }
417        if view_set_name.as_str() == "thread_spans" {
418            // The thread_spans branch: stream-scoped, no process_id or stream_id column --
419            // resolve through `streams`. Same canonicalization as the async_events branch, keyed
420            // on `stream_id` instead of `process_id`.
421            if skip {
422                return Ok(None);
423            }
424            let stream_id_literal = Self::canonical_view_instance_id(&view_set_name, &view)?;
425            return Ok(Some(self.exists_for_stream(
426                per_process_audience,
427                resolved_predicate,
428                stream_id_literal.as_str(),
429            )?));
430        }
431        Err(DataFusionError::Plan(format!(
432            "OwnershipRewrite: no audience rule defined for view set '{view_set_name}'"
433        )))
434    }

436    fn rewrite_plan(
437        &self,
438        plan: LogicalPlan,
439        per_process_audience: &LogicalPlan,
440        resolved_predicate: &Expr,
441        in_subquery_plan: &Arc<LogicalPlan>,
442    ) -> datafusion::error::Result<Transformed<LogicalPlan>> {
443        let LogicalPlan::TableScan(ts) = &plan else {
444            return Ok(Transformed::no(plan));
445        };
446        let Some(table_source) = ts.source.downcast_ref::<DefaultTableSource>() else {
447            return Ok(Transformed::no(plan));
448        };
449        let Some(mat_view) = table_source
450            .table_provider
451            .downcast_ref::<MaterializedView>()
452        else {
453            // Not a MaterializedView (e.g. a table function's output) -- nothing to filter.
454            return Ok(Transformed::no(plan));
455        };
456        let Some(predicate) = self.predicate_for(
457            &ts.table_name,
458            mat_view,
459            per_process_audience,
460            resolved_predicate,
461            in_subquery_plan,
462        )?
463        else {
464            // No predicate: a public view set, or a guarded `view_instance(...)` scan
465            // the call-level guard already authorized.
466            return Ok(Transformed::no(plan));
467        };
468        let filter = Filter::try_new(predicate, Arc::new(plan.clone()))?;
469        Ok(Transformed::yes(LogicalPlan::Filter(filter)))
470    }
471}
472
473impl AnalyzerRule for OwnershipRewrite {
474    fn name(&self) -> &str {
475        "ownership_rewrite"
476    }
477
478    fn analyze(
479        &self,
480        plan: LogicalPlan,
481        _options: &ConfigOptions,
482    ) -> datafusion::error::Result<LogicalPlan> {
483        if self.read_scope == ReadScope::All {
484            // The internal/maintenance marker -- never a ReadPolicy's output. A true no-op, not
485            // "filter to a set containing everything" (see the module doc comment).
486            return Ok(plan);
487        }
488        let per_process_audience = self.per_process_audience()?;
489        let resolved_predicate = self.resolved_predicate();
490        let in_subquery_plan = Self::in_subquery_plan(&per_process_audience, &resolved_predicate)?;
491        plan.transform_up_with_subqueries(|node| {
492            self.rewrite_plan(
493                node,
494                &per_process_audience,
495                &resolved_predicate,
496                &in_subquery_plan,
497            )
498        })
499        .map(|res| res.data)
500    }
501}
