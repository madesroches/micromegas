1//! `OwnershipRewrite` -- Query Enforcement Prong A (#1370, AbAC Stage 2).
2//!
3//! An `AnalyzerRule` that injects an audience-filtering predicate into every
4//! `MaterializedView`-backed `TableScan` a query plan touches, based on the caller's `ReadScope`
5//! (#1369, AbAC Stage 1, `read_scope.rs`) and the two deployment knobs bundled in
6//! [`super::read_scope::IsolationConfig`] (`MICROMEGAS_UNSTAMPED_AUDIENCE`,
7//! `MICROMEGAS_PUBLIC_VIEW_SETS`). See `tasks/1370_ownership_rewrite_plan.md` for the full design
8//! rationale; this comment records only what a future reader of this file needs close at hand.
9//!
10//! ## `ReadScope::All` is a true no-op
11//!
12//! `ReadScope::All` is the internal/maintenance marker -- never the output of a real `ReadPolicy`
13//! (see `read_scope.rs`). `analyze()` returns the plan unchanged when constructed with it, and
14//! `query.rs::make_session_context` does not even construct this rule for `ReadScope::All`
15//! callers, so their `ViewFactory` need not carry `processes`/`streams` either.
16//!
17//! ## One audience per process, not per row
18//!
19//! `__processes__partitions` (the raw, un-merged `SqlBatchView` partitions `self.processes_source`
20//! scans) can carry more than one historical row per `process_id` -- the partition-level
21//! `GROUP BY` in `processes_view.rs`'s transform query only collapses rows *within* a partition,
22//! not across a long-lived process's entire history. Filtering those raw rows directly (a bare
23//! `WHERE <audience predicate>`) would let a process admitted once, by any one of its historical
24//! (possibly pre-stamping, unstamped) rows, stay visible forever to whatever audience that row
25//! happened to carry -- even after the process is later stamped with a real, narrower audience.
26//! Every branch below therefore resolves one audience per process first
27//! (`Aggregate(GROUP BY process_id, MAX(audience) AS resolved_audience)`, `MAX` over a nullable
28//! column ignoring `NULL`s so a stamped row always outranks an unstamped one), then filters
29//! *that* -- uniformly, including `processes`'s own scan, which gets no separate per-row branch.
30//! This assumes a process is stamped with at most one distinct audience over its lifetime (true
31//! under Stage 5's design). Stage 3 (#1371, `audience_guard.rs`) landed without revisiting this --
32//! Prong B resolves straight from Postgres's current row, so the assumption doesn't even arise
33//! there the way it does for this rule's own historical, multi-row aggregate.
34//!
35//! ## Branch table
36//!
37//! Keyed on `MaterializedView::get_view().get_view_set_name()` and whether
38//! `get_file_schema()` has a `process_id` field -- not on a hardcoded view-set list, so a future
39//! view set with a `process_id` column falls into §4 automatically:
40//!
41//! | View set | `process_id` column? | Branch |
42//! |---|---|---|
43//! | `processes` | yes (and *is* the audience source) | §3: `process_id IN (subquery)` against its own resolved-per-process aggregate |
44//! | `streams`, `blocks`, `log_entries`, `measures`, `net_spans`, `otel_spans`, `images`, `log_stats` | yes | §4: semi-join, `process_id IN (subquery)` (outer `process_id` cast to `Utf8`: it is `Dictionary(Int32, Utf8)` in most of these, and nothing coerces an uncorrelated `IN` subquery's join keys once `DecorrelatePredicateSubquery` turns it into a `LeftSemi` join -- the analyzer's own `TypeCoercion` has already run by the time this rule executes) |
45//! | `async_events` | no -- process-scoped, but no column to join on | §5: literal-valued `EXISTS`, keyed on `get_view_instance_id()` (the process_id string, canonicalized -- see `canonical_view_instance_id`) |
46//! | `thread_spans` | no -- stream-scoped, no `process_id` **or** `stream_id` column | §6: two-hop literal `EXISTS`, through `streams` (`get_view_instance_id()` is the stream_id string, canonicalized the same way) |
47//! | anything in `public_view_sets` | (any) | §7: no predicate at all -- checked before any of the above |
48//! | anything else | (any) | `analyze()` returns `Err` (`DataFusionError::Plan`) rather than silently leaving the scan unfiltered -- a future view set must add itself to this table, not fall through |
49//!
50//! Adding a new view set to a `ViewFactory` means adding it to this table too, and to the match
51//! arms in [`OwnershipRewrite::predicate_for`] below.
52//!
53//! ## No I/O in `analyze()`
54//!
55//! `in_subquery`/`exists` build uncorrelated subquery `Expr`s; `DecorrelatePredicateSubquery` (an
56//! optimizer, not analyzer, rule) turns them into joins later. `processes_source`/`streams_source`
57//! come from `MaterializedView::new(..., query_range: None)`, which is synchronous and does no I/O
58//! -- the actual `processes`/`streams` scans happen during normal execution, exactly like
59//! `TableScanRewrite`'s injected time filter.
60//!
61//! ## `micromegas.audience` is now server-written and authenticated (AbAC Stage 5, #1373, landed)
62//!
63//! [`Self::audience_col`] reads `micromegas.audience` via `property_get` off the `processes`
64//! view's `properties` column. Before Stage 5 this was a verbatim snapshot of whatever
65//! `ProcessInfo.properties` the instrumented client sent at ingestion, with no reserved-key
66//! filtering and no server-side validation. Stage 5 closed that gap: ingestion now strips any
67//! client-supplied `micromegas.*` property and writes `micromegas.audience` itself from the
68//! authenticated credential's `AuthContext.bound_audience` (each ingestion key is assigned
69//! exactly one write audience, Stage 4, #1372) -- a client can no longer assert or suppress the
70//! stamp. Registration itself (`insert_process`/`register_otel_process`) now also rejects a
71//! same-`process_id`, different-audience re-registration outright -- needed because the OTLP
72//! `process_id` derivation formula is public, so without this guard a credential could
73//! pre-register (via the native path) the exact `process_id` a victim audience's OTLP producer
74//! would later derive, silently exposing that audience's data to the squatter; this is a
75//! confidentiality gap, not merely an integrity one. What remains open, tracked separately: a
76//! credential bound to one audience that knows another audience's already-registered
77//! `process_id`/`stream_id` can still append events to it over `insert_stream`/`insert_block`
78//! (Stage 5b, an integrity-only gap -- see `rust/ingestion/src/web_ingestion_service.rs`'s doc
79//! comments on those two methods). A second, distinct residual gap sits in the conflict guard
80//! itself: its existing-`NULL`-audience branch is deliberately a no-op (so a mid-migration
81//! re-registration doesn't lose its process), which lets an audience-less credential
82//! pre-register a victim's future `process_id` unstamped -- the victim's later, genuine
83//! registration then hits that same `NULL`→no-op branch and never gets stamped, permanently
84//! suppressing its audience (a confidentiality gap, not an integrity one). There is no
85//! in-product enforcement knob left for this gap; the mitigation is operational -- provision
86//! only audience-bound DB-backed ingestion credentials, and don't run ingestion with an
87//! env-keyring key, OIDC, or `--disable-auth` alongside them -- see the "Residual gap"
88//! admonition in `mkdocs/docs/admin/authentication.md` and this stage's `CHANGELOG.md` entry).

110/// Injects an audience predicate into every `MaterializedView` scan (see the module doc comment).
111pub struct OwnershipRewrite {
112    read_scope: ReadScope,
113    unstamped_audience: Option<String>,
114    public_view_sets: Vec<String>,
115    processes_source: Arc<dyn TableSource>,
116    streams_source: Arc<dyn TableSource>,
117}

119impl std::fmt::Debug for OwnershipRewrite {
120    /// `dyn TableSource` carries no `Debug` impl, so `processes_source`/`streams_source` are
121    /// named but not expanded.
122    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
123        f.debug_struct("OwnershipRewrite")
124            .field("read_scope", &self.read_scope)
125            .field("unstamped_audience", &self.unstamped_audience)
126            .field("public_view_sets", &self.public_view_sets)
127            .field("processes_source", &"<dyn TableSource>")
128            .field("streams_source", &"<dyn TableSource>")
129            .finish()
130    }

133impl OwnershipRewrite {
134    /// `processes_source`/`streams_source` must be built from `MaterializedView::new(...,
135    /// query_range: None)` over the raw partitions (equivalent to `__processes__partitions` /
136    /// `__streams__partitions`) -- see `query.rs::make_session_context` and Design §2 of
137    /// `tasks/1370_ownership_rewrite_plan.md` for why: the audience lookup must be time-unbounded,
138    /// and must not go through the `SqlBatchView`-merged `processes`/`streams` named tables.
139    pub fn new(
140        read_scope: ReadScope,
141        unstamped_audience: Option<String>,
142        public_view_sets: Vec<String>,
143        processes_source: Arc<dyn TableSource>,
144        streams_source: Arc<dyn TableSource>,
145    ) -> Self {
146        Self {
147            read_scope,
148            unstamped_audience,
149            public_view_sets,
150            processes_source,
151            streams_source,
152        }
153    }
154
155    /// `property_get(properties, AUDIENCE_PROPERTY)`, cast to `Utf8`. `property_get` returns
156    /// `Dictionary(Int32, Utf8)` (`property_get.rs`), and this rule runs strictly *after*
157    /// DataFusion's built-in `TypeCoercion` analyzer pass (`Analyzer::new()`'s only two built-ins
158    /// are `[ResolveGroupingFunction, TypeCoercion]`), so nothing coerces the expressions it
159    /// injects -- every one of them is explicitly typed here instead. The property name itself is
160    /// [`AUDIENCE_PROPERTY`] (`audience_guard.rs`), Prong B's constant too -- one definition
161    /// shared by both prongs, rather than each inlining its own copy of the literal.
162    fn audience_col() -> Expr {
163        cast(
164            ScalarUDF::from(PropertyGet::new())
165                .call(vec![col("properties"), lit(AUDIENCE_PROPERTY)]),
166            DataType::Utf8,
167        )
168    }
169
170    /// `Aggregate(GROUP BY process_id, MAX(audience_col) AS resolved_audience)` over the raw,
171    /// time-unbounded `processes` partitions -- built once per `analyze()` call and reused at
172    /// every scan site the traversal visits (see the module doc comment).
173    fn per_process_audience(&self) -> datafusion::error::Result<LogicalPlan> {
174        LogicalPlanBuilder::scan(
175            "__processes__partitions",
176            self.processes_source.clone(),
177            None,
178        )?
179        .aggregate(
180            vec![col("process_id")],
181            vec![max(Self::audience_col()).alias("resolved_audience")],
182        )?
183        .build()
184    }
185
186    /// The caller's audience set. Only ever called after `analyze()` has short-circuited on
187    /// `ReadScope::All`, so the `All` arm here is unreachable in practice; it degrades to "no
188    /// audiences" rather than panicking if that invariant is ever violated.
189    fn audiences(&self) -> &[String] {
190        match &self.read_scope {
191            ReadScope::All => &[],
192            ReadScope::Audiences(a) => a,
193        }
194    }
195
196    /// `coalesce(resolved_audience, unstamped_audience) IN (audiences)`, or `lit(false)` when
197    /// `audiences` is empty -- the fail-closed reading of "caller has no audiences" rather than
198    /// emitting `IN ()` and leaving its behavior to DataFusion (`ReadScope::Audiences` can
199    /// legitimately resolve to an empty set -- a caller matching no grant resolves to `{public}`,
200    /// but a bare-array read-only audience with no matching selector contributes nothing).
201    ///
202    /// `coalesce` is applied to the already-aggregated `resolved_audience` column, never to the
203    /// pre-aggregate, per-row audience expression: applying it per row first would let the
204    /// constant default outrank a real stamped value under `MAX`'s plain string ordering (e.g.
205    /// `"alice-laptop"` sorts below `"public"`), silently resolving a stamped process to the
206    /// wrong audience.
207    fn resolved_predicate(&self) -> Expr {
208        let audiences = self.audiences();
209        if audiences.is_empty() {
210            return lit(false);
211        }
212        let resolved_audience = match &self.unstamped_audience {
213            Some(u) => coalesce(vec![
214                col("resolved_audience"),
215                lit(ScalarValue::Utf8(Some(u.clone()))),
216            ]),
217            None => col("resolved_audience"),
218        };
219        resolved_audience.in_list(
220            audiences
221                .iter()
222                .map(|a| lit(ScalarValue::Utf8(Some(a.clone()))))
223                .collect(),
224            false,
225        )
226    }
227
228    /// §3/§4's shared `IN`-subquery plan: `per_process_audience` filtered by `resolved_predicate`,
229    /// projected down to `process_id` alone -- the one column an `InSubquery` may project.
230    fn in_subquery_plan(
231        per_process_audience: &LogicalPlan,
232        resolved_predicate: &Expr,
233    ) -> datafusion::error::Result<Arc<LogicalPlan>> {
234        Ok(Arc::new(
235            LogicalPlanBuilder::from(per_process_audience.clone())
236                .filter(resolved_predicate.clone())?
237                .project(vec![col("process_id")])?
238                .build()?,
239        ))
240    }
241
242    /// §5's literal-valued `EXISTS`: `per_process_audience` filtered down to the single process
243    /// named by `process_id_literal`, conjuncted with `resolved_predicate`. No projection: unlike
244    /// `InSubquery`, `EXISTS` has no single-column-projection requirement, so the two-column
245    /// (`process_id`, `resolved_audience`) shape is fine.
246    fn exists_for_process(
247        per_process_audience: &LogicalPlan,
248        resolved_predicate: &Expr,
249        process_id_literal: &str,
250    ) -> datafusion::error::Result<Expr> {
251        let subquery = LogicalPlanBuilder::from(per_process_audience.clone())
252            .filter(
253                col("process_id")
254                    .eq(lit(process_id_literal))
255                    .and(resolved_predicate.clone()),
256            )?
257            .build()?;
258        Ok(exists(Arc::new(subquery)))
259    }
260
261    /// §6's two-hop literal `EXISTS`: resolve `stream_id_literal` (the `thread_spans`
262    /// `view_instance_id`) through `streams` into the process it belongs to, then apply the same
263    /// `per_process_audience`/`resolved_predicate` check §5 uses directly.
264    fn exists_for_stream(
265        &self,
266        per_process_audience: &LogicalPlan,
267        resolved_predicate: &Expr,
268        stream_id_literal: &str,
269    ) -> datafusion::error::Result<Expr> {
270        let subquery =
271            LogicalPlanBuilder::scan("__streams__partitions", self.streams_source.clone(), None)?
272                .filter(col("stream_id").eq(lit(stream_id_literal)))?
273                .join(
274                    LogicalPlanBuilder::from(per_process_audience.clone())
275                        .filter(resolved_predicate.clone())?
276                        .build()?,
277                    JoinType::Inner,
278                    (vec!["process_id"], vec!["process_id"]),
279                    None,
280                )?
281                .build()?;
282        Ok(exists(Arc::new(subquery)))
283    }
284
285    /// Parses `view.get_view_instance_id()` as a `Uuid` and returns its canonical
286    /// lowercase-hyphenated string form -- the form actually stored in `process_id`/`stream_id`
287    /// columns. `Uuid::parse_str` accepts several equivalent textual spellings (uppercase,
288    /// hyphen-less, braced) of the same UUID, but
289    /// only this canonical form round-trips through the data; using the raw, caller-supplied
290    /// spelling directly in a literal comparison would silently fail to match for any other
291    /// spelling of a legitimately materialized instance id. Defensive `Err` on parse failure --
292    /// the view constructors (`AsyncEventsView::new`/`ThreadSpansView::new`) already validate this
293    /// as a UUID at construction time, so this should not happen in practice.
294    fn canonical_view_instance_id(
295        view_set_name: &Arc<String>,
296        view: &Arc<dyn super::view::View>,
297    ) -> datafusion::error::Result<String> {
298        let raw = view.get_view_instance_id();
299        Uuid::parse_str(raw.as_str())
300            .map(|uuid| uuid.hyphenated().to_string())
301            .map_err(|e| {
302                DataFusionError::Plan(format!(
303                    "OwnershipRewrite: view set '{view_set_name}' view_instance_id '{raw}' is \
304                     not a valid UUID: {e}"
305                ))
306            })
307    }
308
309    /// Builds the predicate to wrap `mat_view`'s scan in. `Ok(None)` means "no predicate at all"
310    /// (§7's public-view-set skip); `Err` is §7's fallback for a view set matching none of the
311    /// branches -- see the module doc comment's branch table.
312    fn predicate_for(
313        &self,
314        table_name: &TableReference,
315        mat_view: &MaterializedView,
316        per_process_audience: &LogicalPlan,
317        resolved_predicate: &Expr,
318        in_subquery_plan: &Arc<LogicalPlan>,
319    ) -> datafusion::error::Result<Option<Expr>> {
320        let view = mat_view.get_view();
321        let view_set_name = view.get_view_set_name();
322        if self
323            .public_view_sets
324            .iter()
325            .any(|s| s.as_str() == view_set_name.as_str())
326        {
327            return Ok(None);
328        }
329        // Qualified with the outer scan's own table name: once `DecorrelatePredicateSubquery`
330        // joins this scan with `in_subquery_plan`'s subquery, the combined schema holds a
331        // `process_id` column from both sides (for §3, the *same* underlying table on both
332        // sides of a self-referential join), so a bare, unqualified `col("process_id")` is
333        // ambiguous and `into_optimized_plan()` fails.
334        let outer_process_id = Expr::Column(Column::new(Some(table_name.clone()), "process_id"));
335        if view_set_name.as_str() == "processes" {
336            // §3: the audience source's own scan -- same `process_id IN (subquery)` shape as §4.
337            // No cast needed: `processes.process_id` (the outer scan's own column) is already
338            // `Utf8`, unlike most of §4's outer views.
339            return Ok(Some(in_subquery(
340                outer_process_id,
341                in_subquery_plan.clone(),
342            )));
343        }
344        if view.get_file_schema().field_with_name("process_id").is_ok() {
345            // §4: process_id-**column** views (streams, blocks, log_entries, measures, net_spans,
346            // otel_spans, images, log_stats).
347            return Ok(Some(in_subquery(
348                cast(outer_process_id, DataType::Utf8),
349                in_subquery_plan.clone(),
350            )));
351        }
352        if view_set_name.as_str() == "async_events" {
353            // §5: process-scoped, no process_id column -- the view_instance_id *is* the
354            // process_id string (`AsyncEventsView::new` parses it as a `Uuid`). Canonicalized
355            // before building the literal -- see `canonical_view_instance_id`'s doc comment for why.
356            let process_id_literal = Self::canonical_view_instance_id(&view_set_name, &view)?;
357            return Ok(Some(Self::exists_for_process(
358                per_process_audience,
359                resolved_predicate,
360                process_id_literal.as_str(),
361            )?));
362        }
363        if view_set_name.as_str() == "thread_spans" {
364            // §6: stream-scoped, no process_id or stream_id column -- resolve through `streams`.
365            // Same canonicalization as §5, keyed on `stream_id` instead of `process_id`.
366            let stream_id_literal = Self::canonical_view_instance_id(&view_set_name, &view)?;
367            return Ok(Some(self.exists_for_stream(
368                per_process_audience,
369                resolved_predicate,
370                stream_id_literal.as_str(),
371            )?));
372        }
373        Err(DataFusionError::Plan(format!(
374            "OwnershipRewrite: no audience rule defined for view set '{view_set_name}'"
375        )))
376    }
377
378    fn rewrite_plan(
379        &self,
380        plan: LogicalPlan,
381        per_process_audience: &LogicalPlan,
382        resolved_predicate: &Expr,
383        in_subquery_plan: &Arc<LogicalPlan>,
384    ) -> datafusion::error::Result<Transformed<LogicalPlan>> {
385        let LogicalPlan::TableScan(ts) = &plan else {
386            return Ok(Transformed::no(plan));
387        };
388        let Some(table_source) = ts.source.downcast_ref::<DefaultTableSource>() else {
389            return Ok(Transformed::no(plan));
390        };
391        let Some(mat_view) = table_source
392            .table_provider
393            .downcast_ref::<MaterializedView>()
394        else {
395            // Not a MaterializedView (e.g. a table function's output) -- nothing to filter.
396            return Ok(Transformed::no(plan));
397        };
398        let Some(predicate) = self.predicate_for(
399            &ts.table_name,
400            mat_view,
401            per_process_audience,
402            resolved_predicate,
403            in_subquery_plan,
404        )?
405        else {
406            // §7: public view set -- no predicate.
407            return Ok(Transformed::no(plan));
408        };
409        let filter = Filter::try_new(predicate, Arc::new(plan.clone()))?;
410        Ok(Transformed::yes(LogicalPlan::Filter(filter)))
411    }
412}
413
414impl AnalyzerRule for OwnershipRewrite {
415    fn name(&self) -> &str {
416        "ownership_rewrite"
417    }
418
419    fn analyze(
420        &self,
421        plan: LogicalPlan,
422        _options: &ConfigOptions,
423    ) -> datafusion::error::Result<LogicalPlan> {
424        if self.read_scope == ReadScope::All {
425            // The internal/maintenance marker -- never a ReadPolicy's output. A true no-op, not
426            // "filter to a set containing everything" (see the module doc comment).
427            return Ok(plan);
428        }
429        let per_process_audience = self.per_process_audience()?;
430        let resolved_predicate = self.resolved_predicate();
431        let in_subquery_plan = Self::in_subquery_plan(&per_process_audience, &resolved_predicate)?;
432        plan.transform_up_with_subqueries(|node| {
433            self.rewrite_plan(
434                node,
435                &per_process_audience,
436                &resolved_predicate,
437                &in_subquery_plan,
438            )
439        })
440        .map(|res| res.data)
441    }
