Constants§

DEFAULT_LOCAL_SINK_MAX_LEVEL
Default max level for the local (stdout) sink, applied when neither an explicit builder call nor LOCAL_SINK_MAX_LEVEL_ENV_VAR sets one.
DEFAULT_TELEMETRY_SINK_MAX_LEVEL
Default max level for the HTTP telemetry sink, applied when neither an explicit builder call nor TELEMETRY_SINK_MAX_LEVEL_ENV_VAR sets one.
LOCAL_SINK_MAX_LEVEL_ENV_VAR
Environment variable capping the local (stdout) sink’s max level. Read once by TelemetryGuardBuilder::build. Precedence is TelemetryGuardBuilder::with_local_sink_max_level (including the #[micromegas_main] macro’s local_sink_max_level attribute) > this variable > the DEFAULT_LOCAL_SINK_MAX_LEVEL default. Accepts off, fatal, error, warn, info, debug, or trace, case-insensitively; an unparseable value fails build().
PROCESS_PROPERTIES_ENV_VAR
Environment variable carrying deployment-supplied process properties as a comma-separated key=value list, e.g. cluster=prod,role=cache. Read by TelemetryGuardBuilder::build, so every micromegas process honors it.
TELEMETRY_SINK_MAX_LEVEL_ENV_VAR
Environment variable capping the HTTP telemetry sink’s max level. Read once by TelemetryGuardBuilder::build. Precedence is TelemetryGuardBuilder::with_telemetry_sink_max_level > this variable > the DEFAULT_TELEMETRY_SINK_MAX_LEVEL default. Accepts the same values as LOCAL_SINK_MAX_LEVEL_ENV_VAR; an unparseable value fails build(), even if no telemetry URL ends up configured.

Functions§

merge_process_properties
Merges a PROCESS_PROPERTIES_ENV_VAR-formatted list into properties, leaving keys already present untouched. Precedence is therefore explicit TelemetryGuardBuilder::with_process_property calls > environment > populate_default_system_properties defaults: an operator can add deployment tags but cannot spoof the version that micromegas_main stamps nor the identity properties derived from the host, both of which dashboards filter on. Within one list the first occurrence of a key wins, consistent with that rule.
