Shared harness for the micromegas and opentelemetry bench binaries.

Both binaries use the same group and case ids so report.py can pair the libraries by the ids criterion records in benchmark.json.

Constants§

BATCH
Operations emitted between two drains, across all threads. The OpenTelemetry batch queue holds 2048 records by default and drops on full, so a chunk this size can never overflow it.
SERIES_COUNTS
Series per metric batch: each batch is one value for each of this many series.
THREAD_COUNTS

Functions§

bench_cases
Times only the emits: after each chunk of at most BATCH operations, drain runs outside the timed region so the background thread always starts a chunk with an empty queue.
bench_contention
Runs each case on 1, 4 and 8 threads that start together and use disjoint counter ranges. The reported throughput is the aggregate of all threads. Threads emit BATCH / threads operations per chunk and meet at a barrier; the main thread drains between chunks. A chunk costs the slowest thread’s emit time, measured inside the thread so barrier wake-up latency stays out of it.
print_bytes
One line per encoded sample, parsed by report.py (criterion has no custom-metric output).

Type Aliases§

AfterCase
Called once per case after its last sample with the case id (group/case/lib, or contention/case/lib/threads) and the number of operations it emitted. Panics if the library dropped any of them.
Case
One recorded operation; the argument is a persistent counter so high-cardinality ids stay new.
Drain
