# Update Grafana SDK from 11.6 to 12.x Plan

**GitHub Issue**: https://github.com/madesroches/micromegas/issues/848

## Overview
Upgrade the Grafana plugin (`grafana/`) frontend dependencies from the Grafana 11.6.7 plugin SDK to the latest stable 12.x line (12.3.3), including replacing the frozen `@grafana/experimental` package with its successor `@grafana/plugin-ui`, refreshing the `@grafana/create-plugin`-scaffolded tooling in `.config/`, and bumping the Grafana version used for local dev/e2e testing to 12.x.

## Current State
- `grafana/package.json` pins `@grafana/data`, `@grafana/runtime`, `@grafana/ui` to exact `11.6.7`, and `@grafana/e2e-selectors` to `11.6.7` as a dev dependency.
- `@grafana/experimental@^2.1.6` is used in three files for the SQL query builder:
  - `grafana/src/components/QueryEditor.tsx` — `MacroType`
  - `grafana/src/components/RawEditor.tsx` — `LanguageDefinition`, `SQLEditor`
  - `grafana/src/components/utils.ts` — `LanguageCompletionProvider`, `getStandardSQLCompletionProvider`
  - `@grafana/experimental`'s published peer dependencies cap `@grafana/data`/`@grafana/ui`/`@grafana/runtime` at `^10.4.0 || ^11.0.0` — it is not declared compatible with 12.x and hasn't been published since 2.1.6, so it must be replaced.
- `@grafana/ui` components used elsewhere (`Select`, `HorizontalGroup`, `InlineField`, `Modal`, `Checkbox`, etc., across `grafana/src/components/*.tsx`) are all still exported in `@grafana/ui@12.3.3` — confirmed by inspecting `12.3.3`'s type declarations. Some (`Select`, `HorizontalGroup`) are marked deprecated in favor of `Combobox`/`Stack` but remain functional, so no component migration is required for this upgrade.
- `.config/` (webpack, jest, tsconfig, prettier, eslint scaffolding) is generated by `@grafana/create-plugin` and carries a "DO NOT EDIT" banner in every file (e.g. `grafana/.config/webpack/webpack.config.ts:2`). There is no `@grafana/create-plugin` dev dependency recorded in `package.json` today, so the scaffolding was likely generated once via `npx` and never re-synced.
- `grafana/docker-compose.yaml` defaults `GRAFANA_VERSION` to `11.6.7` for the local/e2e test Grafana instance (`docker-compose up`, used by `yarn server` and the Playwright `webServer` in `playwright.config.ts`).
- `grafana/src/plugin.json:54` declares `"grafanaDependency": ">=9.2.5"` — this is a minimum version floor, not a pin, and does not need to change since no 12.x-only API is being adopted.
- `@grafana/tsconfig` is pinned `^2.0.1` (latest `2.2.0`) and `@grafana/eslint-config` is pinned `^9.0.0` (latest `10.0.0`) — the issue explicitly calls these out for review.
- CI (`.github/workflows/grafana-plugin.yml`) runs `yarn typecheck`, `yarn lint`, `yarn test:ci`, `yarn build`, then boots `yarn server -d` and runs `yarn e2e` (Playwright) against the dockerized Grafana instance — this is the main correctness gate for this upgrade.
- Grafana's official migration guide for this range (`update-from-grafana-versions/migrate-11_6_x-to-12_0_x`) only documents breaking changes to the plugin **extension API** (`usePluginExtensions`, `getPluginLinkExtensions`, `AppPlugin.configureExtensionLink`, etc., replaced by `addLink`/`addComponent`/`usePluginLinks`/`usePluginComponents`) and the `Select`/`MultiSelect` → `Combobox`/`MultiCombobox` deprecation. Micromegas's plugin doesn't implement any plugin extension points (checked `grafana/src/module.ts`, `grafana/src/plugin.json` — no `extensions` block), so none of the extension-API changes apply. There is no separate guide for 12.0→12.3 (no additional breaking changes documented in that range).

## Design

### Dependency changes (`grafana/package.json`)
| Package | Current | Target |
|---|---|---|
| `@grafana/data` | `11.6.7` | `12.3.3` |
| `@grafana/runtime` | `11.6.7` | `12.3.3` |
| `@grafana/ui` | `11.6.7` | `12.3.3` |
| `@grafana/e2e-selectors` (dev) | `11.6.7` | `12.3.3` |
| `@grafana/experimental` | `^2.1.6` | removed |
| `@grafana/plugin-ui` (new) | — | `^0.17.3` |
| `@grafana/tsconfig` (dev) | `^2.0.1` | `^2.2.0` |
| `@grafana/eslint-config` (dev) | `^9.0.0` | `^10.0.0` |
| `@grafana/plugin-e2e` (dev) | `^3.0.0` | `^3.10.0` |

React (`^18.0.0`) and Node (`.nvmrc` = `20`) requirements are unchanged — `@grafana/data`/`@grafana/ui`/`@grafana/runtime@12.3.3` still peer-depend on React 18, and `@grafana/create-plugin`'s `engines.node` is `>=20`.

### `@grafana/experimental` → `@grafana/plugin-ui` swap
`@grafana/plugin-ui@0.17.3` re-exports the same SQL-editor primitives under the same names (confirmed via its type declarations): `SQLEditor`, `LanguageDefinition`, `LanguageCompletionProvider`, `getStandardSQLCompletionProvider`, `MacroType`. This is expected to be a drop-in import-path rename with no call-site logic changes:
- `grafana/src/components/QueryEditor.tsx:4` — `import {MacroType} from '@grafana/experimental'` → `from '@grafana/plugin-ui'`
- `grafana/src/components/RawEditor.tsx:3` — `import {LanguageDefinition, SQLEditor} from '@grafana/experimental'` → `from '@grafana/plugin-ui'`
- `grafana/src/components/utils.ts:1` — `import {LanguageCompletionProvider, getStandardSQLCompletionProvider} from '@grafana/experimental'` → `from '@grafana/plugin-ui'`

### `.config/` scaffolding refresh
Rather than hand-editing the generated webpack/jest/tsconfig files, regenerate them with the official updater so they match what a fresh 12.x plugin scaffold looks like:
```
npx @grafana/create-plugin@latest update
```
Review the diff it produces (it may touch `.config/`, `tsconfig.json`, `.eslintrc`/`eslint.config.mjs`, `package.json` scripts) and reconcile with the project's existing customizations (e.g. this repo builds from `webpack.config.ts` rather than the default `.config` entrypoint directly — verify that wrapper still composes correctly after the update).

### Local/e2e test environment
Bump the default Grafana test image in `grafana/docker-compose.yaml`:
```yaml
grafana_version: ${GRAFANA_VERSION:-12.3.3}
```
so `yarn server` / the CI e2e job exercise an actual Grafana 12 instance, satisfying the issue's "Test against a Grafana 12 instance" task.

## Implementation Steps

1. **Bump frontend SDK dependencies**
   - In `grafana/package.json`, update `@grafana/data`, `@grafana/runtime`, `@grafana/ui`, `@grafana/e2e-selectors` to `12.3.3`.
   - Remove `@grafana/experimental`; add `@grafana/plugin-ui@^0.17.3`.
   - Bump `@grafana/tsconfig` to `^2.2.0`, `@grafana/eslint-config` to `^10.0.0`, `@grafana/plugin-e2e` to `^3.10.0`.
   - Run `yarn install` from `grafana/` and commit the updated lockfile entries (root `yarn.lock`).

2. **Swap `@grafana/experimental` imports**
   - Update the three import statements listed above in `QueryEditor.tsx`, `RawEditor.tsx`, `utils.ts` to import from `@grafana/plugin-ui`.
   - Run `yarn typecheck` to confirm the replacement types line up (props/generics for `SQLEditor`, `LanguageCompletionProvider` should be identical, but verify).

3. **Refresh generated scaffolding**
   - Run `npx @grafana/create-plugin@latest update` from `grafana/`.
   - Diff the result against the current `.config/`, `tsconfig.json`, `webpack.config.ts`, eslint config; keep intentional project customizations (custom webpack wrapper, docker-compose old-plugin-version mount, etc.) and accept upstream scaffold changes otherwise.

4. **Bump local/CI Grafana test version**
   - Update `grafana/docker-compose.yaml` default `GRAFANA_VERSION` to `12.3.3`.

5. **Fix fallout**
   - Run `yarn typecheck`, `yarn lint:fix`, `yarn test:ci`, `yarn build` in `grafana/` and resolve any type/lint errors surfaced by the SDK bump (expected to be minor — no breaking API usage was found in research, but `Select`/`HorizontalGroup` deprecation warnings from ESLint's `@grafana/eslint-config@10` may newly flag existing usages; address or suppress per lint output).
   - Run `yarn server -d && yarn e2e` (Playwright) against the Grafana 12.3.3 docker instance; fix any UI regressions surfaced by the real browser tests (this is the step most likely to surface actual behavior changes, since 12.x visual/DOM diffs for `Select`/`Modal`/`Checkbox` aren't captured by unit tests).

6. **Update CHANGELOG**
   - Add an entry to `grafana/CHANGELOG.md` noting the SDK bump to 12.3.3.

## Trade-offs
- **Full `create-plugin update` vs. hand-editing versions only**: hand-editing just the SDK versions in `package.json` is lower-risk/lower-effort, but the `.config/` scaffolding is explicitly marked as generated and may embed 11.x-specific webpack/jest assumptions (e.g. SWC/TS target, plugin.json schema validation rules) that only the official updater knows how to migrate correctly. Given the issue explicitly asks to follow the migration guide and this repo hasn't run the updater before, running it is the safer choice, accepting the extra review diff it produces.
- **`@grafana/plugin-ui` vs. keeping `@grafana/experimental`**: `@grafana/experimental` might still work at runtime against 12.x despite its peer dependency range (peer dep warnings aren't hard failures), but relying on an unmaintained package with declared incompatibility is fragile and the replacement is a same-name drop-in, so there's no reason to keep it.
- **Not migrating `Select`→`Combobox` / `HorizontalGroup`→`Stack` now**: both are deprecated but not removed in 12.3.3. Migrating them is a larger, purely cosmetic/API-surface change unrelated to this issue's scope (dependency bump); tracking as a follow-up rather than bundling in.

## Testing Strategy
- `yarn typecheck` and `yarn lint` in `grafana/` — catch type/lint regressions from the SDK bump.
- `yarn test:ci` — existing Jest unit tests (`datasource.test.ts`, `ConfigEditor.test.tsx`, `types.test.ts`) must continue to pass.
- `yarn build` — verify webpack production build succeeds against the new SDK/scaffolding.
- `yarn server -d && yarn e2e` — boot the plugin against a real Grafana 12.3.3 instance via docker-compose and run the Playwright smoke test (`tests/smoke.spec.ts`), satisfying the issue's "test against a Grafana 12 instance" requirement.
- Manual sanity check: open the query builder and raw SQL editor views in the running Grafana 12 instance to confirm the `@grafana/plugin-ui` `SQLEditor` swap renders and autocompletes correctly (this is the one behavior change unit tests won't catch).

## Open Questions
- Should `grafanaDependency` in `plugin.json` (currently `>=9.2.5`) be raised to reflect the new minimum tested version (e.g. `>=11.0.0`), or left as a broad floor since no 12.x-only API is being consumed? Leaving as-is is lower risk for existing installs; raising it is more honest about what's actually tested going forward.
- `@grafana/create-plugin@latest update` is an interactive/generative step whose exact diff can't be predicted without running it — implementation should budget time to review and reconcile its output rather than assume a mechanical version bump.
