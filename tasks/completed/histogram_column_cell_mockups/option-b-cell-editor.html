Table cell editor — "Render as": Markdown or Histogram

Every override card now has exactly two render kinds: Markdown (today's only option — the Format field) or Histogram (a color mode for a column that's already a histogram by default). One column, one card, one place to look for "how does this column render."

"Render as" only appears when the selected column is histogram-typed (detected via isHistogramStructType against the query result's schema, which the panel doesn't currently see — availableColumns gains a sibling availableColumnTypes map; see plan Design §6). For every other column the card looks exactly like it does today — just the Format field, no toggle.

Picking Histogram swaps the Format textarea for six colormap swatches — each an actual gradient, not a name you have to know or type — plus one custom-color swatch backed by the OS color picker. Click a colormap swatch and each bucket samples that scale by its own height; pick a custom color and every bar gets that one flat color instead. No text field, no help-text paragraph to read: the swatches themselves are what's on offer, and the ring around one shows which is active. The live bars at the bottom of the card update immediately. No card at all still means a plain default-colored histogram — a card only exists to customize it.

There's no separate debug feature. Switching a histogram column's card to Markdown with $row.duration_dist as the Format dumps its raw fields instead of charting it — the same Format field every other override already uses, just pointed at a column that now formats usefully as text.
